# v1.6.0 (archived release summary)

This summary uses current product terminology. For historical installation commands
and exact image names, consult the original Git tag. Use the current README for
new installations and the upgrade guide for existing data.

Ullavox puts the conversation first. The redesigned interface brings chat and research into a calmer workspace, makes each model's provider visible, and keeps advanced settings within reach. Optional local preferences, projects and explicitly saved project notes help carry useful context between chats.

## What's new

- A quieter conversation layout with responsive navigation, a focused composer, collapsible research activity, and accessible context and settings panels.
- Model choices show their connection/provider so you can see where models are fetched from. Selecting a cloud model still sends enabled context to that provider.
- Optional preferences for response style, familiarity and working instructions. Skip onboarding and return through Preferences whenever useful.
- Projects group chats and provide shared instructions. Save, review, edit and pin project notes explicitly; chat does not automatically extract memories.
- Per-chat inclusion controls and Context used explain which preferences and project notes were supplied. Note selection is bounded text matching, not semantic search over every past chat.
- Versioned SQLite migration preserves supported existing histories. Application and Ollama ports now bind to localhost by default.
- Credential-file exclusions and automated secret scanning for pull requests and main.

## Install

The historical package requires Docker and Docker Compose.

Use the original tagged release asset for this version’s installation commands.

Open http://localhost:8080. The Compose asset selects the image pinned by the original release asset. The default `granite4:3b` model downloads once into a named volume (about 2.1 GB). Ollama's image and model tags remain mutable. Set `OLLAMA_MODEL` in an adjacent `.env` file to choose another default; existing conversations keep their selected models.

The APIs have no login protection. Keep this as a trusted, single-user installation. Ports bind to `127.0.0.1` by default; deliberately overriding the original bind-address setting to `0.0.0.0` exposes them to other machines. Run one Ullavox application process per database.

## Capabilities and data handling

Chat, text-file analysis and bounded web research continue from v1.5.0. Attach at most four text, Markdown, CSV, JSON or code files with 24,000 combined characters. PDF/Office documents, editing files and executing code are unsupported. Image input requires a vision-capable model. Agent web work has at most five search/page-reading calls; tool results and conversation context have bounded budgets. Cancellation takes effect after an in-flight request returns.

History, preferences and saved project notes persist in local SQLite without new database encryption. Included context goes to the selected model, including a cloud model when selected. Files-only disables web tools; it does not make cloud inference local. Web queries and requested URLs go to the configured external provider, and generated queries can contain enabled context. Parallel remains optional; see [provider setup](https://github.com/manojisnow/ullavox/blob/v1.6.0/docs/parallel-search.md).

Project notes remain after their source chat is reset or deleted. Delete notes separately to remove them from future retrieval. Disabling or deleting saved context does not remove references from old replies or retract data previously sent to a provider. See [preferences and project memory](https://github.com/manojisnow/ullavox/blob/v1.6.0/docs/local-memory.md) for controls and limits.

Model outputs, calculations and citations still need review. Sources and Context used show supplied evidence; they do not prove an answer's correctness.

## Upgrade, backup and rollback

1. Keep the existing Compose directory and project name so Docker selects the same named volumes. Never use `docker compose down -v` for an upgrade.
2. Stop the app with `docker compose -f COMPOSE_FILE stop app`. Get its ID with `docker compose -f COMPOSE_FILE ps -aq app`, then copy the complete data directory using `docker cp CONTAINER_ID:/app/data ./ullavox-backup-before-1.6.0`. Keep database, WAL and SHM files together. Store this private backup outside Git. For a live source, use SQLite's backup API instead of copying the database file alone.
3. Save the old Compose file, `.env`, project name and image version. Keep the prior image available.
4. After publication, download the v1.6.0 Compose file into that directory, review configuration and start it. Supported legacy schemas migrate to versioned ownership/preferences/project tables while preserving history. Existing chats begin without a project and with empty global preferences. Unknown schemas fail migration rather than silently discard data.
5. Validate existing chats, new chat, file follow-ups, enabled web research, preferences and project notes. Restart and confirm persistence before accepting the upgrade.
6. To roll back, stop the new app and keep its upgraded data separately. Restore the complete pre-upgrade data directory as one set, including matching WAL/SHM files and writable ownership for the original container account. Restore the previous Compose/image and the same project name. Do not run the old binary against the migrated database. Changes since the backup are absent after rollback.
