# v1.5.0 (archived release summary)

This summary uses current product terminology. For historical installation commands
and exact image names, consult the original Git tag. Use the current README for
new installations and the upgrade guide for existing data.

The release Compose health check uses `ollama list`, so startup does not depend on curl being installed in the Ollama image.

Ullavox adds bounded agent research and file analysis, reliable follow-ups, collapsible activity, and optional Parallel search and public-page reading. Generation-setting reset, model overrides and same-origin API defaults are fixed. Java, Spring Boot and frontend tooling are upgraded; coverage checks are enforced.

## Install

The release Compose file selects the image pinned by the original release asset, rather than a moving `latest` image. Docker and Docker Compose are required.

Use the original tagged release asset for this version’s installation commands.

Open http://localhost:8080. The default [IBM Granite 4 3B](https://ollama.com/library/granite4:3b) model (`granite4:3b`, about 2.1 GB) downloads on first start. Set `OLLAMA_MODEL` in an adjacent `.env` file to choose another model. The default changes from phi4-mini; existing conversations keep their selected model. Model behavior varies: a completed agent run does not prove correct arithmetic or factual claims, and some models may not invoke tools reliably. Inspect answers and sources. The image tag pins Ullavox, but Ollama still uses `latest`, and downloaded model tags and external services can change.

Ullavox is intended here for a trusted, single-user installation. Its APIs have no authentication and the Compose ports bind to all interfaces. Restrict network access; do not expose this setup to an untrusted network.

## Agent capabilities and limits

- Ask naturally in Agent mode; tool names are unnecessary. Tools operate within the selected Files-only or Web scope.
- Attach up to four text, Markdown, CSV, JSON or code files, with at most 24,000 characters combined. PDF and Office documents, file editing and code execution are unsupported. Image input requires a vision-capable model and is separate from text-file analysis.
- Follow-ups retain files and web scope. New uploads replace files of the same name; Clear retained files removes their availability for subsequent tasks. Files remain stored in conversation history.
- Memory is bounded: agent history and prior retrieved evidence each have an 8,000-character budget. Web tasks share at most five search/page-reading calls; each result is capped at 4,000 characters. This is not unlimited conversation memory.
- Review uses the same model as drafting. Citation validation checks whether URLs occur in available evidence, not whether every claim is true. Retrieved excerpts may be incomplete or outdated. If the reviewed answer omits links, Ullavox displays up to five available web-source links from the evidence; their presence does not prove every claim.
- Cancellation takes effect at a checkpoint after an in-flight request returns. Server restart interrupts active tasks; they are marked failed for retry.

## External-data handling

Text attachments and history are stored in the local SQLite database. Selecting a cloud model sends task input, including attached content, to that model provider. Files-only prevents web-tool calls; it does not make a cloud model local.

Legacy web search remains the default. Set `WEB_SEARCH_PROVIDER=parallel` to opt in to Parallel MCP search and page reading. An optional backend-only `PARALLEL_API_KEY` enables authenticated access. Anonymous access is for light use, with provider-controlled limits. Queries and requested page URLs go to the configured search provider. Parallel also receives a random per-conversation identifier and the active model name; Ullavox does not automatically send complete files or conversation history to Parallel, although model-generated queries can contain task information.

Read [Parallel setup and terms considerations](https://github.com/manojisnow/ullavox/blob/v1.5.0/docs/parallel-search.md) before enabling it, particularly for personal data or hosted use. Provider access is not bundled with Ullavox.

## Upgrade, backup and rollback

Keep the original Compose project name: Docker uses it to select the existing named volumes. Changing the project name can make history appear missing by selecting a new volume. Do not use `docker compose down -v` when upgrading or rolling back.

1. Stop the existing app before copying its database: `docker compose -f COMPOSE_FILE stop app`.
2. Obtain its container ID with `docker compose -f COMPOSE_FILE ps -aq app`, then copy the entire stopped data directory using `docker cp CONTAINER_ID:/app/data ./ullavox-backup-before-1.5.0`. Keep any SQLite WAL/SHM files together with the database. Store this backup privately; it contains conversation data.
3. Save the previous Compose file and `.env`, note the old project name and image version, and keep the previous image available. If backing up a running database instead, use SQLite's backup API or `.backup`, not a plain copy of the original database file.
4. Download the v1.5.0 Compose file to the same project directory, review `.env`, and start it. Validate existing history, ordinary chat, file follow-ups and any enabled web research. The database adds a nullable web-session identifier while preserving history.
5. To roll back, stop the new app, restore the complete backup into its mounted `/app/data` directory as one set, replacing the upgraded database and any associated WAL/SHM files; never mix an older database with newer WAL files, and restore ownership so the original container account can write it. Select the previous pinned Ullavox image in the saved Compose file and start it with the same project name. Keep the upgraded database separately until rollback is verified; changes made after the backup are not included in the restored database.

See [framework migration details](https://github.com/manojisnow/ullavox/blob/v1.5.0/docs/framework-upgrade.md) for runtime requirements and database compatibility notes.
